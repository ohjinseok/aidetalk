# 위젯 임베드 가이드

## 설치 스니펫

사이트에 아래 두 줄만 넣으면 됩니다. `workspaceId`는 대시보드 > 워크스페이스 설정에서
확인할 수 있습니다.

```html
<script>
  window.AideTalk = { workspaceId: "ws_xxx" };
</script>
<script async src="https://{host}/widget.js"></script>
```

`{host}`는 여러분이 셀프호스팅한 AideTalk 서버의 공개 주소(`SERVER_URL`)입니다.

이 스니펫 자체는 MIT 라이선스입니다 — 자유롭게 사이트에 붙여넣고 필요하면 수정하세요.

## 동작 원리 (로더 / 본체 2단계)

- **로더(`widget.js`, 2KB 미만)**: 의존성 없는 순수 JS입니다. `workspaceId`가 있는지 확인하고,
  Shadow DOM 컨테이너를 만든 뒤 본체를 비동기로 불러옵니다. 본체 로드에 실패해도 호스트
  사이트에 어떤 에러도 던지지 않습니다.
- **본체(`app.js`, 버전 경로로 서빙, 최대 50KB gzip)**: 실제 UI(Preact + Shadow DOM)와
  WebSocket 연결, 재연결/폴백 로직을 담고 있습니다.

이렇게 나눠져 있어서 로더 스크립트를 사이트에 다시 붙여넣지 않아도 본체만 재배포하면
업데이트가 반영됩니다.

## CSP 지침

Content-Security-Policy를 쓰는 사이트라면 아래 지시문이 필요합니다(`{host}`를 실제
서버 도메인으로 치환하세요).

```
script-src {host};
connect-src {host} wss://{host};
```

- `script-src`: 로더/본체 스크립트를 불러오기 위해 필요합니다.
- `connect-src`: WebSocket 연결(`wss://{host}/ws/visitor`)과 long-poll 폴백에 쓰는
  HTTP 요청을 허용하기 위해 필요합니다.

### nonce를 쓰는 사이트

`strict-dynamic`과 `nonce`를 함께 쓰는 CSP라면, 로더 스크립트 태그에 nonce를 그대로
붙이면 됩니다.

```html
<script nonce="{your-nonce}">
  window.AideTalk = { workspaceId: "ws_xxx" };
</script>
<script async nonce="{your-nonce}" src="https://{host}/widget.js"></script>
```

`strict-dynamic`이 있으면 nonce가 붙은 스크립트가 동적으로 로드하는 후속 스크립트(본체)도
신뢰되므로, 본체 스크립트 태그에 별도 nonce를 붙일 필요는 없습니다.

## SPA / 플랫폼별 주의사항

### SPA(Next.js, React Router 등 클라이언트 라우팅)

위젯은 최초 마운트된 이후 페이지 라우팅과 무관하게 유지됩니다 — 클라이언트 사이드
라우팅으로 페이지를 이동해도 위젯이 다시 마운트되거나 대화가 끊기지 않습니다. 다만
`page_url`(에이전트에게 전달되는 방문자 정보 중 하나)은 **세션이 시작된 시점의 URL로
고정**됩니다. 방문자가 라우팅으로 다른 페이지로 이동해도 이 값은 갱신되지 않습니다(v1
단순화된 동작입니다).

### 카페24 / 아임웹 등 국내 쇼핑몰 빌더

::: warning 실사이트 검증 진행 중
카페24/아임웹처럼 관리자 화면에서 스크립트를 삽입하는 플랫폼별 세부 주의사항(스크립트
삽입 위치, iframe 제약, CSP 기본 설정 등)은 아직 실사이트로 검증하지 않았습니다
(로드맵 M2 항목). 추측으로 단정하지 않기 위해 이 섹션은 검증 후 갱신할 예정입니다.
:::

일반적으로는 플랫폼의 "외부 스크립트 삽입" 또는 "HTML/CSS 편집" 기능으로 `<head>` 혹은
`</body>` 직전에 위 설치 스니펫을 넣는 방식이 통용됩니다. 다만 플랫폼에 따라 관리자가
스크립트에 자체 CSP를 씌우거나 특정 위치에서만 스크립트 실행을 허용하는 경우가 있어,
설치 후 반드시 위젯 런처가 보이는지·메시지 전송이 되는지 직접 확인해 보세요. 문제가
있다면 GitHub 이슈로 플랫폼명과 증상을 남겨주시면 이 문서를 갱신하는 데 큰 도움이 됩니다.

## 트래킹 파라미터 at_l

AideTalk는 "상담이 매출에 얼마나 기여했는지"를 추정하기 위해 상담 중 보낸 링크 클릭을
추적합니다. 이 값은 **인과관계를 확정하는 지표가 아니라 기여를 추정하는 지표**입니다
— 대시보드에서도 항상 "상담 기여 매출(추정)"이라고 표기됩니다.

동작 순서는 다음과 같습니다.

1. Agent(또는 상담원)가 대화 중 URL이 포함된 답변을 보내면, AideTalk가 URL에
   `?at_l={토큰}` 파라미터를 자동으로 붙여 발송합니다. 원본 URL만 넣으면 되고, 별도
   작업은 필요 없습니다.
2. 방문자가 그 링크를 눌러 사이트로 재진입하면, 위젯 **로더**(본체 로드보다 먼저)가
   URL의 `at_l` 파라미터를 감지해 클릭을 서버에 보고하고, `history.replaceState`로
   파라미터를 주소창에서 제거합니다. 이 동작은 본체 로드 성공 여부와 무관하게 항상
   최우선으로 실행됩니다(트래킹 유실 방지).
3. (로드맵 예정) 결제 완료 페이지에 넣는 별도의 전환 스크립트가 주문 완료 시점을
   서버에 알리면, 최근 클릭 기록과 연결해 "이 상담이 이 주문에 기여했다"를 추정합니다.

`at_l` 파라미터가 붙은 링크를 공유하거나 캐시하지 마세요 — 방문자별 추적 토큰이라
다른 사람에게 전달되면 추적이 부정확해질 수 있습니다.

`at_l` 기반 클릭 추적과 전환 추정 기능은 사이트가 있는 워크스페이스(S1)에서만
활성화됩니다.
