# 00_PRD.md — 제품 요구사항

> 한국 SMB를 위한 오픈소스 CS 메신저. AI Agent를 가장 쉽게 붙일 수 있는 고객 상담 플랫폼.
> 버전 v1.0 (확정) — 이 문서의 범위(§4)와 Non-goals(§2.3)가 기능 구현 여부의 최종 판단 기준이다.

## 1. 한 줄 정의

**"채널톡의 한국형 오픈소스 대안. 내가 만든 AI Agent를 5분 만에 내 사이트 채팅 위젯에 연결한다."**

- 배포 모델: **Open Core** — 셀프호스팅 무료(AGPL-3.0), 클라우드 유료 SaaS (상세: 01_BUSINESS_MODEL.md)
- 차별점 우선순위:
  1. (Main) 한국 SMB에 맞는 오픈소스 CS — 한국어 UX, 세금계산서, 국내 결제(PG 미정), 존댓말 어투 프리셋
  2. (Sub) AI Agent BYO — Claude Code/Codex로 만든 에이전트를 HTTP 커넥터로 그대로 연결
  3. (Sub) 예측 가능한 저렴한 가격 — LLM 비용 유저 부담(BYO Key)이므로 종량 폭탄 없음
  4. (Growth) CS를 매출 엔진으로 — 매출 전환 트래킹 + 실시간 상담 어시스트

## 2. 배경 / 문제 정의

### 2.1 시장 상황
- **채널톡**: 종량제 개편 이후 SMB 가격 불만 폭증. MU/시트/ALF/PU/CU 등 과금 단위 복잡 → 청구액 예측 불가.
- **카카오 카나나 상담매니저**: 무료지만 카카오톡 채널 내부 전용. 자사몰 연동·커스텀 AI 불가.
- **Chatwoot 등 해외 OSS**: 기능은 충분하나 영어 UI/문서, 한국 결제·세무 미지원 → 한국 채택률 극히 낮음.
- **AI 환경 변화**: Claude Code/Codex/Cursor 확산으로 자기 에이전트를 만드는 개인·소규모 팀 급증. 그러나 만든 에이전트를 **고객 접점(웹 채팅)에 붙이는 마지막 구간**이 비어 있음.

### 2.2 해결하는 문제 (우선순위순)
| # | 문제 | 누구의 문제 |
|---|---|---|
| P1 | CS 메신저가 비싸고 청구액 예측 불가 | 한국 SMB 대표/운영자 |
| P2 | 직접 만든 AI Agent를 내 사이트 채팅에 붙일 방법이 없음 | 개발 가능한 1인 창업자/인디해커 |
| P3 | 외산 OSS는 한국 환경(언어/결제/세무/어투)에 안 맞음 | 한국 SMB 전체 |
| P4 | AI 응답 실패 시 사람이 받아줄 인박스가 없음 | P2와 동일 |
| P5 | 상담이 실제 구매로 이어졌는지 알 수 없음 → CS 투자 근거 부재 | 이커머스/서비스 (S1) |
| P6 | 상담 품질이 상담원 개인 역량에 좌우됨 | 상담원 여러 명 두는 SMB |

### 2.3 안 풀 문제 (Non-goals, v1) — 구현 요청이 와도 거부
- ❌ 카카오톡 채널/네이버 톡톡/인스타 DM 등 외부 메신저 통합 (v2+ 별도 PRD)
- ❌ 마케팅 메시지 발송 (알림톡/문자 캠페인)
- ❌ 아웃바운드 전화/콜센터
- ❌ 자체 LLM 호스팅 / 자체 AI 모델 제공 (BYO 원칙)
- ❌ 팀 메신저(사내 채팅)

## 3. 타겟 사용자

### Persona A — "빌더형 창업자" (v1 핵심 타겟)
1~5인 스타트업/자사몰. 코드를 직접 짜거나 Claude Code로 만들 수 있음. 자기 에이전트를 만들었거나 만들 의지 있음.
Pain: "에이전트는 만들었는데 고객이 쓸 채팅 UI + 운영 인박스가 없다."
경로: GitHub 발견 → 셀프호스팅 → 운영 귀찮아지면 클라우드 전환.

### Persona B — "채널톡 이탈 SMB" (확장 타겟, M3 이후)
5~30인. 개발자 0~1명, 클라우드 선호. Pain: 비용 예측 불가.
메시지: "채널톡 대비 n분의 1 가격 + 데이터 소유권."

### 3.1 세그먼트 경계 — "사이트 있음"이 기능을 가른다
| 세그먼트 | 예시 | 이 제품에서의 위치 |
|---|---|---|
| **S1. 사이트 있는 곳** | 자사몰, SaaS, 예약형 서비스 | **v1 메인.** 위젯 + 에이전트 + 매출 전환 트래킹 + 어시스트 전부 성립 |
| **S2. 사이트 없는 곳** | 학원·공방·미용실·식당 | v1.5+ 확장. 호스팅 링크 destination + 예약. 매출 트래킹 대신 행동(예약) 트래킹 |

- **매출 전환 트래킹은 S1 전용.** 결제 페이지가 온라인에 있어야 성립. S2에는 UI 자체를 노출하지 않는다.
- 워크스페이스 생성 시 `segment` 값(`s1_site` / `s2_no_site`)을 받아 저장 → 기능 노출 분기 근거.

## 4. 제품 범위 (v1 = MVP)

### 4.1 핵심 사용자 여정
```
[사업자]
1. docker compose up (셀프호스팅) 또는 클라우드 가입
2. 워크스페이스 생성 → 위젯 스크립트 1줄 복사 → 사이트에 삽입
3. (선택) AI Agent 연결: endpoint URL 등록 → shared secret 1회 발급
4. 고객 문의 → AI 1차 응답 → 실패/요청 시 핸드오프
5. 인박스에서 사람이 이어받아 응대. 상담 어시스트가 실시간 보조.
6. 대시보드에서 "상담 기여 매출(추정)" 확인 (S1)

[방문자]
1. 사이트 우하단 채팅 버튼 클릭
2. 회원가입 없이 즉시 채팅 (이메일은 선택 수집)
3. AI/상담원과 대화, 페이지 이동·재방문에도 대화 유지
```

### 4.2 기능 목록 (MoSCoW)

#### Must (없으면 출시 불가)
| 기능 | 수용 기준 |
|---|---|
| 채팅 위젯 | 카페24·아임웹·Next.js 사이트에서 깨짐 없이 동작. Shadow DOM 격리, SPA/새로고침 세션 유지, 모바일 대응. 번들 ≤50KB gzip |
| 실시간 메시징 | 네트워크 단절 10초 후 재연결 시 메시지 유실 0, 순서 보장, 중복 0 |
| 상담 인박스 | 상담원 2명이 같은 대화를 충돌 없이 처리. 목록 실시간 갱신 |
| AI Agent 커넥터 | curl로 검증 가능한 공개 스펙(05 문서). 타임아웃/실패 시 자동 핸드오프 |
| 휴먼 핸드오프 | 핸드오프 후 AI 호출 중단, 이전 대화 컨텍스트 상담원에게 표시, "AI에게 반환" 가능 |
| 셀프호스팅 배포 | README만 보고 30분 내 `docker compose up -d`로 구동 |
| 워크스페이스/멤버 | owner/agent_member 역할, 멤버 초대 |
| 한국어 UX | 전체 UI 한국어 기본, 어투 프리셋(formal/casual) |

#### Should (v1 포함 목표)
- 고객 프로필(이메일/이름/커스텀 속성), 위젯 색상·인사말 커스터마이즈, 운영시간 설정
- AI 응답 로그 뷰어(agent_logs)
- **매출 전환 트래킹(S1)** — §4.4. v1은 링크 태깅 + 클릭 추적까지. 전환 스크립트는 v1.5
- **실시간 상담 어시스트** — §4.5. v1은 답변 초안 제안까지
- 대화 검색(단순 텍스트), 웹훅(conversation.created/closed)

#### Could (여유 시)
- FAQ 간이봇(에이전트 없는 유저 폴백), Slack 알림, CSV export

#### Won't — §2.3 Non-goals

### 4.3 AI Agent 커넥터 (제품의 심장)
유저 에이전트는 언어/프레임워크 무관, HTTP 계약(05_AGENT_PROTOCOL.md)만 지키면 연결된다.
- 동기 HTTP, 타임아웃 기본 30초 → 초과 시 자동 핸드오프 + 안내 메시지.
- HMAC-SHA256 서명으로 위조 방지.
- 스타터 예제 2종(Node/Python) 제공. 예제 README 첫 줄: "이 레포를 Claude Code에 열고 '우리 쇼핑몰 정책에 맞게 고쳐줘'라고 하세요." — 예제가 곧 온보딩.

### 4.4 매출 전환 트래킹 (S1 전용)
**목표: "이 상담이 ₩얼마의 구매로 이어졌나"를 상담 단위로 보여준다.** 가치는 정확한 인과 증명이 아니라 사장님이 CS의 매출 기여를 눈으로 보게 하는 것.

흐름:
1. **링크 태깅(v1)**: AI/상담원이 보낸 URL에 `?od_conv=&od_visitor=` 자동 부착 → `tracked_links` 기록
2. **클릭 기록(v1)**: 손님이 링크로 사이트 재진입 → 위젯이 파라미터 감지 → `clicked_at` 기록
3. **전환 수신(v1.5)**: 결제완료 페이지의 1줄 전환 스크립트가 `POST /t/conversion` → 대화 귀속
4. **커머스 API 연동(v2)**: 카페24 등 주문 웹훅
5. **대시보드**: 대화별 "안내 링크/클릭 여부", 워크스페이스 "상담 기여 매출(추정)" 집계

원칙:
- 어트리뷰션은 근사치. UI 문구는 항상 **"상담 기여 매출(추정)"**. 귀속 규칙(라스트클릭 등)은 설정값, 조회 시 계산.
- `conversions.source`(click_only/pixel/commerce_api)로 정확도 등급 구분.
- S2에 노출 금지.

### 4.5 실시간 상담 어시스트
**목표: 상담원 옆에서 AI가 실시간 코칭 → 초보도 잘 팔게.**

- mode=human 대화에 손님 메시지 도착 → 에이전트를 `mode=assist`로 호출 → **상담원에게만 보이는** 사이드 패널에 draft(답변 초안) + rationale(상황 판단) + actions(추천 링크) 표시.
- 상담원은 채택/수정/무시. outcome을 기록해 제안 품질 측정.
- 제안 생성도 유저 에이전트가 담당(BYO 일관). 미구현 에이전트는 noop 반환 → 비활성.
- assist 실패는 핸드오프하지 않고 조용히 스킵(손님 경험 영향 0).
- **전환 트래킹이 어시스트의 연료** (전환된 상담 패턴 → 제안 근거) → 구현 순서상 트래킹이 먼저.

## 5. 비즈니스 모델 — 상세는 01_BUSINESS_MODEL.md
Open Core: 셀프호스팅 무료(AGPL) / Cloud Starter ₩29,000/월 / Cloud Pro ₩79,000/월. 과금 단위는 "월 대화 수 + 시트" 둘만. LLM 비용은 항상 유저 부담(BYO) → 클라우드 마진 80%+ 목표.

## 6. 성공 지표
- **North Star: 주간 활성 워크스페이스(WAW)** — 7일 내 대화 1건 이상 발생한 워크스페이스
- v1 출시 3개월: GitHub Stars 1,000 / 셀프호스팅 설치 200(opt-in 텔레메트리 기준) / WAW 50 / 유료 10팀 / Agent 연결률 40%+ / 위젯 p95 첫 메시지 왕복 <500ms(AI 제외) / 트래킹 활성화율(S1 중) 30%+
- 사전 검증 가설: H1 채널톡 이탈 수요 실재 / H2 빌더는 위젯+인박스를 붙여 쓰길 원함 / H3 BYO Key가 신뢰 요소 / H4 전환 트래킹이 지불 의사↑ / H5 상담원이 AI 제안을 채택함 → M0 인터뷰 5건으로 확인

## 9. 마일스톤 (상세: 11_ROADMAP.md)
- **M0 (2주)**: 검증 — 인터뷰 5건, 네이밍/라이선스, 스캐폴드
- **M1 (7주)**: 코어 — 메시징 + 위젯 + 인박스 + 커넥터 + 트래킹 + 어시스트
- **M2 (3주)**: 셀프호스팅 패키징 + 공개 문서 + 예제
- **M3 (3주)**: 클라우드 알파 + 결제 + 런칭

## 9.5 장기 비전 (v3+, 구현 금지 — 방향만)
도구 → 네트워크 순서를 지킨다. v1은 사장님용 도구(설치 기반 = 사장님 1만 명). v1.5에 링크 destination+예약으로 S2 흡수 → 손님 데이터 축적. v3+에 discovery 레이어(근처 가게 발견)는 기반이 쌓인 후에만. **지금 해둘 단 하나: 손님이 남기는 데이터(어느 가게에 무엇을 문의/전환)를 처음부터 깔끔한 구조로 저장** — visitors/conversations/conversions 스키마가 이를 담당.
